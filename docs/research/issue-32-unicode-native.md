# Research: Text-Fabric feature literals with invisible Unicode (issue #32)

2026-10-11. Context: merged parser PR #30 now escapes *model-facing* Option descriptions without mutating the locally retained corpus value. `CorpusSchema` inventories represent raw `str` values byte-exact and `compile_query` validates every equality/inequality value against this inventory. Compiler `_escape` currently rejects C0/DEL, surrogates and non-space whitespace, then escapes native syntax metacharacters, but passes other `Cf` characters unchanged.

**Existing real-corpus observation:** `tests/test_compiler_adversarial.py::test_hostile_literal_membership_and_negation` already constructs a genuine Text-Fabric corpus containing `x\u200e` (U+200E LEFT-TO-RIGHT MARK), and verifies native TF search output against independently enumerated raw data for EQ and NE (also inside /without/ quantifiers). Its passing CI is positive evidence that **at least U+200E** works without normalization in TF 13.1.0. Therefore blanket rejection of `Cf` would remove a previously verified, useful round-trip and should not happen without additional rationale.

**Risk classification and research plan:** Differentiate script-format helpers U+200C ZERO WIDTH NON-JOINER, U+200D ZERO WIDTH JOINER, U+200E LEFT-TO-RIGHT MARK and U+200F RIGHT-TO-LEFT MARK (used in written languages, direction marking and NLP corpora) from formatting controls that *visually mislead native query review*: U+200B ZERO WIDTH SPACE, U+202A..U+202E bidi embedding/override, U+2060..U+206F (word joiner, invisible mathematical operators, directional isolates, deprecated bidi controls), U+FEFF ZERO WIDTH NO-BREAK SPACE, and non-printing soft hyphen U+00AD. Unicode `Cf` is not itself identical to a native syntax injection. The first set should be allowed only when native search on a synthetic corpus returns exact, independently measured raw tuples. The second set should be **rejected with sanitized CompileError** despite being corpus-attested: auditability is a valid hard fail-closed safety criterion, even if TF could technically execute them. Preserve all non-NFC combining sequences byte-exact (they are `Mn` marks, not `Cf`). Some other `Cf` may be legitimately part of writing systems (e.g. Arabic letter mark and Indic controls); prefer a targeted hazard list to blanket `Cf` rejection pending additional native evidence.

**Red/green and oracle:** Research/design first, then RED-first tests on actual tiny TF saved through `tf.fabric.Fabric` covering safe, punctuation, NFC-vs-decomposed, accepted format helpers and rejected suspicious format controls. For permitted values compare compiled EQ and NE Text-Fabric results to *raw* `api.Fs(...).data`, not a hand-authored query oracle; for rejects assert no native template can be generated, and error message does not print input value. Add multi-value EQ and NE tests where one forbidden literal is embedded in an otherwise valid set, preventing partial-match fallbacks. Include U+202E in an unselected feature value/metadata and assert selecting a safe literal remains valid. Parser description handling stays a distinct layer and must not be coupled to compiler's literal policy.

**Scope:** Local typed compiler hardening, no new grammar, no parser prompt changes, no benchmark/data files modified, no external corpus downloads. Full Python 3.11–3.13 CI runs real TF synthetic tests, then independent adversarial review of exact final PR head. Any uncovered TF 13.1.0 mismatch in the allowed set triggers refinement of explicit policy rather than weakening native equality assertions.
