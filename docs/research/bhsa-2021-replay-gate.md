# Why #10 needs a real BHSA replay gate

2026-10-11. Grounded in existing `tests/conformance/tf_harness.py`, `tests/conftest.py`, `scripts/nl_benchmark.py`, `scripts/nl_candidates.py`, official BHSA notebook source and upstream Git `tf/2021` tree `c7b070bc5e9950371c1f17c183bd9bd57e5e63e2`.

Current normal GitHub Actions CI executes the tiny synthetic Text-Fabric corpus, but all real BHSA tests are opt-in and **38 tests skip**. Current candidate intake records 18 notebook examples; 14 are explicitly replayable, 4 deferred. Historical notebook results are not BHSA 2021 gold: searchFromMQL pinned 2017 and other notebooks were unversioned. Without a real-corpus run, #10 cannot expand its reproducible gold benchmark soundly.

**Reproducible source contract.** Official `ETCBC/bhsa` repository commit `4db00e2157915495e1a4d3d57e41223df24775da` has `tf/2021`. Its source tree `c7b070bc5e9950371c1f17c183bd9bd57e5e63e2` is about 165 MiB across 118 entries. A GitHub-hosted Linux runner should clone *only* `tf/2021` with a sparse, blob-filtered checkout of that exact commit, verify its actual checkout SHA and zero source changes, then invoke TF 13.x native API. No Text-Fabric corpus snapshot is committed to this repository. `scripts.nl_benchmark.verify_source` authenticates 7 required files, while `scripts.nl_candidates.verify_candidate_source` authenticates 16 and prevents arbitrary mutable on-disk data. In GitHub Actions, Git itself also verifies the complete commit history/tree when cloning.

**Performance and failure modes.** Loading TF has nontrivial RAM usage; the expensive `extract_schema` code in issue #20 is NOT needed for native replay. A 500,000 row cap per native candidate is enough for the documented 426,590-word example and ensures clear errors on unexpectedly huge expansions. TF search errors can otherwise look like empty result sets, so `run_template` uses `_msgCache` and fails closed. Replay both the existing six gold cases and all 14 in-scope tutorial candidates **in one loaded TF session** to reduce load overhead. Abort on malformed/invalid sources or gold count mismatch. For candidate failure, capture error with an explicit failing gate and never turn it into a purported gold result.

**Data/license and security.** BHSA is CC BY-NC 4.0. Only execute research-oriented checks; do not redistribute text, per-node records or massive result tuple dumps. A tiny JSON summary of **counts and case IDs** is adequate; include Git commit/provenance and stable fixture digests and record independent review. No model calls, credentials, secrets, or network from Python runner. Fetch public BHSA only in a designated CI job, not in normal local/unit CI. Restrict GitHub workflow privileges to `contents: read`, and make normal CI continue operating offline.

**Acceptance scope.** A green targeted replay gate establishes exact *native execution/cardinality* on the pinned corpus. It does **not** establish candidate English meaning, expressibility in compiler QueryIR, or semantic model accuracy; these require separate human/independent review and held-out controls. #10 stays open until independently validated examples are promoted and benchmark breadth reaches useful coverage.
