# Research: avoid expanding optimized Text-Fabric otype to a huge dictionary (#20)

Pinned upstream code is decisive: [Text-Fabric v13.1.0 `tf/core/otypefeature.py`](https://github.com/annotation/text-fabric/blob/v13.1.0/tf/core/otypefeature.py) defines **`OtypeFeature`**, which differs from ordinary [`NodeFeature`](https://github.com/annotation/text-fabric/blob/v13.1.0/tf/core/nodefeature.py). Ordinary `NodeFeature.items()` delegates to `.data.items()`, but **`OtypeFeature.data` is a compact sequence of non-slot type names, not a mapping**; slots `1..maxSlot` all share `slotType`. Its `.items()` explicitly generates `(node,type)` tuples over `1..maxNode` using compact data and indices. This corrects the initial research note: replacing `dict(api.F.otype.items())` with `api.F.otype.data` directly would be invalid. That intermediate implementation was never merged.

Current `src/tf_jev/schema.py::_extract` materializes a full node→type dictionary from this compact `OtypeFeature.items()`, although native TF already provides all types via index arithmetic. The dict is used for type count/interval checks, per-feature type partitioning, edge validation and historical effective-data hashing; it is transient and not retained in the immutable snapshot.

Optimization: an internal immutable **mapping view** over the already-loaded compact OtypeFeature stores only four scalar/reference fields, implements `Mapping[int,str]` with `__iter__ = iter(range(1,maxNode+1))`, `__len__ = maxNode`, and `__getitem__` using `slotType` for nodes <=maxSlot, and `data[node-maxSlot-1]` otherwise. The Python `Mapping` mixin supplies `.get/.items/.values` and `__contains__` without materializing the full dictionary. The producer already disallows simultaneous corpus mutation during extraction. The view is strictly local and not saved in CorpusSchema. Canonical `sorted(node_types.items())` and hash serialization stay byte-identical.

**Observed RED:** CI 38240287849, Python 3.12 test `test_extraction_borrows_existing_tf_otype_mapping_without_copy` fails precisely at `dict(api.F.otype.items())`, with 503 other tests passing and 41 skipped. The test uses a saved real TF corpus and independently validates equal identity, inventories, compiler text and native verb tuples.

**Real BHSA gate:** Pinned public BHSA 2021 full SHA `70150b50dab4ba75908146225ec450652256e2471d131f6106cd3bdaac19e82d`, full+selected profilers and compiled/native exact 73,710 tuples via existing schema-profile Actions. Whole-process time and RSS are noisy; do not infer general speedups from one shared runner. Improvement is avoidance of one huge Python dict allocation, while JSON hashing and loaded TF features still dominate memory.
