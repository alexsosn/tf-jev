# Research: opt-in feature-scoped CorpusSchema, real BHSA 2021 (#37)

Baseline from exact pinned TF 13.1.0 / ETCBC/bhsa 2021: 109 node/3 edge features; stage `load_features` 40.85s, `node_features` 22.76s, extraction 72.62s, process peak 4.703 GB (PR #36). These are whole-process measurements and are NOT guaranteed minimum improvements.

Current code `extract_schema(api)` unconditionally loads all admissible TF node/edge features. It hashes all *effective loaded* values + metadata, validates all nodes/edges, retains exact feature inventories for the compiler, and computes `CorpusIdentity.loaded_sha256`, module location/source hashes, identity key, and Large lookup handles. Caller-supplied **subset coverage** must be distinguishable from source corpus absence: `sp` not loaded is an unknown, not proof of no part-of-speech annotation; even presence/absence of feature metadata must not leak into unsupported inference. Additional already-loaded features from `otext` are not covered unless explicitly selected, but their process memory may remain unavoidable.

The schema's full-mode digest is a public provenance contract: do not change it, digest record ordering, reference query semantics, or source-file hashing. For selected mode, add an explicit coverage manifest to the *digest* so two feature subsets never collide even on empty domains, and include the complete set of discovered admissible feature names. The latter list is **names only**, not proof of values. Loaded schema may certify selected features (including all-missing feature domains), not every discovered corpus feature. Non-NFC, empty strings, sparse int values, source overrides and edge directionality remain exact for the selected subset.

The parser's current `SemanticParser` treats its `schema.node_features` as an exhaustive selection list and can confidently choose unsupported when a feature is unavailable. Until a separate partial-awareness decision design is reviewed, **refuse partial schema before calling the decision backend**; deterministic `compile_query` should still work on covered features, fail closed for uncovered source features.

Performance plan: corpus selected-mode profiler with node `sp`, `gn`, `nu` and zero edges. Its output is annotated with `coverage.mode=selected` and feature manifest; workflow uses the immutable upstream commit, TF version and same corpus. Compare to full-mode baseline but never claim isolation from the 1.77 GB core-loaded state; source hashing/warp processing still happen. Confirm native TF result tuples for `word sp=verb` against compiled selected IR. Full-mode BHSA `loaded_sha256` remains `70150b50dab4ba75908146225ec450652256e2471d131f6106cd3bdaac19e82d`.

Implementation has explicit limits: only node and edge feature scoping; no guessed natural-language feature relevance, no automatic partial feature upgrades, and no partial-vs-full model accuracy comparison. Hard error for malformed/duplicate/reserved/unknown requested feature names (not silent skip). Add RED-first tests and independent adversarial review before merging.
