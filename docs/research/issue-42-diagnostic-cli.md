# Research: model-free diagnostic CLI (#42, partial #13)

The installed wheel currently exposes `tf_jev.ir`, `compiler.compile_query`, and `schema.extract_schema` but **no console script**. Issue #13's full natural-language API remains dependent on measured Jev evaluation (#11) and a backend comparison (#12). A limited diagnostic feature can ship independently, exercise native TF end to end, and give researchers immediate results with no credentials.

Verified actual project code: `Predicate`, `Atom` and `Query` dataclasses provide the closed, deterministic intermediate representation; `compiler.compile_query` rejects unknown features, values, type mismatches, unsafe native query literals and unsupported operators; `schema.extract_schema(api, node_features=(...), edge_features=())` supports explicit selected coverage without certifying all corpus features. Its identity is derived from loaded data and local source hashes. For numeric node features, the CLI must convert explicitly typed integer arguments based on the actual schema; string features retain numeric-looking strings.

The real TF 13.1.0 test harness `tests/conformance/tf_harness.py::run_template` calls `api.S.search(template, here=False, limit=..., silent="deep", _msgCache=messages)`, fully consumes generator results, inspects `exe.good` and `tf.core.helpers.wrapMessages(messages)`, and rejects any error diagnostics (including nested search/cutoff). Borrow that **checking contract** for a tiny production adapter; never implement an alternate query interpreter, output raw TF exceptions, or mark truncated results complete. Request up to `limit+1` native tuples to detect a result boundary; treat errors and >limit as failure, not as a successful short list. Return only an aggregate count, never node IDs or corpus text.

For this slice, expose a CLI command `tf-jev compile --corpus DIR --type word --eq sp=verb [--execute --limit 1000]`. Repeated `--eq`, `--present`, `--absent` are converted to a single Atom (without free-form native strings). Explicit `--limit` without `--execute` is an error. All output JSON fields are explicitly designated, with `coverage_mode=selected`; do not call Jev. A fully stable NL API remains out of scope.

Security/ergonomics: no downloads, no `.env` secrets, no model, no user query execution without `--execute`, no success upon overflow or native diagnostics, never write raw exception/corpus values in errors. Isolated installed-wheel E2E smoke should create a tiny native TF corpus and use the real console command. Normal real TF pytest fixtures test compile-only, unknown values, numeric typing, exact native count, and overflow; these tests prove a working researcher-facing path, not Jev accuracy.
