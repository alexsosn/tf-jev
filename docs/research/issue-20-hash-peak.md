# Research: loaded-content digest transient allocations (#20)

Baseline on actual immutable ETCBC/bhsa `tf/2021`, Text-Fabric 13.1.0, Python 3.12; action run 38152228529: **45.909209 s** Fabric core load, **65.281881 s** `extract_schema`; whole-process RSS **1,772,470,272 bytes after load**, **4,191,952,896 after extract** and high-water **4,679,016,448 bytes**. 13 types, 109 admissible node features and 3 edge features. Loaded-content SHA256 `70150b50dab4ba75908146225ec450652256e2471d131f6106cd3bdaac19e82d`. Peak memory is whole-process, not isolated. Cache/data sizes and hosts must be considered before claiming improvement.

`src/tf_jev/schema.py::_extract` hashes each node feature using `_digest_record(loaded_digest, (name, dtype, info.metaData, sorted(api.Fs(name).data.items())))`. The temporary **sorted list of every (node,value) tuple** and then one **fully materialized UTF-8 JSON byte string** are held while complete TF features are resident. Both are avoidable for the same canonical hash. This data may contain values with combining marks, backslashes, empty strings, non-NFC Unicode and very large node counts. The hash authenticates the effective loaded memory snapshot, not merely the source files; **never replace** it with a filename checksum.

Proposed change only to the *large per-node feature hashing representation*: produce exactly the same canonical record as `_json((name, dtype, metadata, sorted(items)))`, including sorting on integer node IDs, JSON metadata `sort_keys=True`, UTF-8 `ensure_ascii=False`, compact punctuation and 8-byte big-endian length-prefix. Iterate sorted **keys** (one integer list, not a tuple per node). Encode blocks of e.g. 4096 pairs using C-backed `json.dumps` and stream the JSON body into a bounded spooled binary temporary file. This avoids a giant JSON string and the full sorted item tuple list. Once byte count is known, stream 8-byte length plus tempfile back into SHA in 1 MiB chunks. The spool uses up to 1 MiB RAM then spills to local scratch storage. This trades some scratch I/O for reduced Python peak. A simpler two-pass streaming approach would duplicate UTF-8 serialization and could make time worse; compare empirically. No strings or records should be sent to CI logs or artifacts.

Research risks: a nonmatching digest or Unicode normalization bug would invalidate all schema identities and handle freshness. Compare exact record bytes/hashes against current `_digest_record` on adversarial fixture; independently assert the **full BHSA** `identity.loaded_sha256` remains exactly `70150b50dab4ba75908146225ec450652256e2471d131f6106cd3bdaac19e82d`. Unit test monitors temporary Python allocated memory using `tracemalloc`, but cannot be mistaken for entire process RSS. Whole-corpus after-change Actions profile will give real data. Do not claim an improvement until this has completed on an exact PR head. Existing source digests, node inventories, edge endpoints, type validation and exact membership semantics remain unchanged. Test-first RED and independent adversarial review required.
