# Research: benchmark-grounded offline parser evaluation (#11, first increment)

Inspected `src/tf_jev/parser.py`, `decisions.py`, `compiler.py`, `scripts/nl_benchmark_v2.py` and the versioned BHSA v2 evidence contract.

- The immutable BHSA 2021 v2 artifact has 109 requests, with entire semantic families held out. Each supported case stores a native query plus **ordered projected distinct** result count and SHA256; ambiguous/unsupported requests intentionally have no gold query. Never tune against heldout or pass case gold/rationale/interpretations to the semantic parser.
- `Benchmark.selected(partition)` defaults to development, and `Benchmark.verify_source` requires the exact corpus TF version and every referenced source hash. `execute(api, query, projection)` rejects native diagnostics, overflow and invalid projection, returning a canonical `(count,signature)`; counts alone are inadequate. Compare the parser's own projection to gold fingerprints; do not infer a projection from gold.
- `SemanticParser.parse(request)` returns `ParseResult(status,reason,ir,query,projection,confidence,evidence,schema_key)`. `compile_query(ir,schema)` is a pure deterministic source of native text. Recompiling before execution defends against forged/stale query fields. Unsupportable parses produce no query.
- `Evidence.receipt` carries backend/model, per-call latency and optional input/output token counts, but no authoritative price. A claimed zero-token cost would be misleading when usage is missing. Timing an evaluation invocation is distinct from the sum of backend receipts; scripted backends prove plumbing, not live Jev accuracy.
- A semantic **supported** success requires a supported parse, verified native execution, and exact gold projected count/signature. A predicted native query with matching row count but different fingerprint is wrong. Gold exact text equality is a separate metric; syntactic alternatives can be result-equivalent.
- For ambiguous/unsupported gold, outputting a query is an unsafe false-positive regardless of whether it happens to return zero rows. `AMBIGUOUS`, `UNSUPPORTED` and `ABSTAINED` are safe nonquery states, though strict classification only credits matching status. `ERROR` is not a correct abstention.
- Candidate-retrieval recall cannot be derived from the final `ParseResult` and remains unmeasured until candidate sets/ground truth are instrumented. A deterministic/scripted evaluation is an end-to-end **harness test**, not a Jev quality benchmark.

Scope this PR to offline scoring of *real parser result objects and native TF execution*, with exhaustive tiny real-TF fixtures, no calls to live services. Later #11 work: pinned live Jev development/heldout run, measurable retrieval recall, backend comparison, end-to-end go/no-go policy. Preserve the exact BHSA corpus source gate for any live report.
