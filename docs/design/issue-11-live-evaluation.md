# Design: pinned BHSA live semantic evaluation entrypoint (#11)

Script-only `scripts.run_jev_evaluation` (not packaged): `run_evaluation(directory: Path, benchmark: Benchmark, backend: DecisionBackend, *, partition: str, max_cases: int, input_usd_per_million=None, output_usd_per_million=None) -> dict[str, Any]`, plus `main(argv: list[str]|None=None) -> int`.

Order: validate partition/max_cases *without side effects*; verify exact pinned source files/version using `benchmark.verify_source(directory)`; load core TF via `Fabric(...).load("", silent="deep")`; extract a **full** CorpusSchema; construct `SemanticParser(schema, backend)`; call `evaluate()` on only the chosen first N canonical cases. Do not manipulate the frozen benchmark itself or modify gold. The returned report has `selection` with partition size, evaluated count, and `complete` boolean; a prefix cannot be mistaken for a full run. JSON reporting uses the existing evaluator's source-safe per-case metrics. Backend is injectable into tests, not model-mocked for quality evidence.

CLI accepts local corpus dir, optional `--partition` (default development), **required positive** `--max-cases`, optional `--input-usd-per-million` and `--output-usd-per-million` (must be supplied together), required `--output`, and `--live`. **Both `--live` and `TF_JEV_LIVE=1`** are required before creating `JevBackend`; fail closed without calling a model or writing a file. No option for arbitrary benchmark path (avoid untrusted benchmarks giving a false impression of verified BHSA). The model is pinned by the existing Jev adapter; credentials come from env and never appear in output. CLI verifies sources BEFORE constructing Jev backend. Write compact JSON via temporary sibling then atomic replace only on success.

Test gates: research and design prior to tests; tests before implementation check tiny real TF source verification, source drift before backend usage, default development and heldout isolation, prefix disclosure, invalid limits/prices, refusal without double live opt-in, and no output on failure. CI 3.11–3.13 Ruff/mypy/pytest/wheel (no real API calls), independent skeptical exact-head code/data review. A real BHSA+Jev run is a separate opt-in acceptance step and must be reported as unavailable if credentials are absent.
