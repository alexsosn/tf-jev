# Design: reproducible native TF replay for #10

1. **Pure runner** `scripts/bhsa_replay.py` accepts `--corpus` and `--output`. It validates version-specific `load_catalog` and `load_candidates`, verifies all pin hashes from both catalogues, loads a single native TF API with the union of needed features, then calls existing `check_gold` and `run_candidate`. The runner intentionally does not compile NL/IR or emit a query.
2. **Output contract** is JSON format version 1, `corpus`, `data_version`, `source_commit`, sha256 hashes of both input dataset JSONs, `gold_checked`, and a list of in-scope tutorial `id`, observed native result count, historical count and provenance version. No raw query or text or result-node IDs in outputs. Stable order follows candidate fixture. Any missing/failed in-scope entry aborts with nonzero exit and no successful report. Explicitly reject output aliasing either fixture to avoid destructive overwrite. Atomically write JSON to a distinct path only after all checks pass.
3. **Opt-in workflow** `.github/workflows/bhsa-replay.yml` triggered only by workflow_dispatch and relevant benchmark changes in pull requests. It uses sparse filtered cloning at an immutable git commit, SHA confirmation, installs repository with dev extras, runs the offline script, and uploads JSON artifact for inspection. No corpus or per-node data are uploaded; 30 min job timeout. Unit tests of the runner use monkeypatched native search and a tiny TF fixture, since the real workflow is the acceptance evidence.
4. **Gate semantics:** RED-first tests assert strict source checks before TF load, abort on native-gold errors, never execute deferred candidate grammar, ensure 14 in-scope successes, protect source fixtures from being overwritten, record immutable Git provenance and fixture hashes, ensure clean error behavior. Tests must not rely on notebook historical counts matching observed 2021 counts.
5. **Review/merge:** native real-corpus job on exact PR head, normal Python CI matrix, separate skeptical review of actual JSON counts and failure modes, then merge. Keep issue #10 open; the promotion to gold happens separately and requires independent linguistic/IR adjudication.
