# Design: memory-bounded canonical hashing for node-feature records

Expose private helper `_digest_node_feature(digest, name, dtype, metadata, data)`, where `data` is mapping[int, str|int]. Replace exactly one `_digest_record` call in `_extract`. Retain all other record formats and domain inventories unchanged. Node IDs must sort numerically regardless of mapping insertion order.

Reference bytes: `json.dumps((name,dtype,metadata,sorted(data.items())), sort_keys=True, ensure_ascii=False, separators=(',', ':'), allow_nan=False).encode('utf8')`. Hash: 8-byte big-endian length followed by these exact bytes, preserving earlier identity snapshots.

Streaming construction: write `[` + JSON(name), JSON(dtype), JSON(metadata), `[` as prefix; then for each chunk of up to 4096 *sorted* IDs, JSON encode its list of [node,value] pairs and strip only its enclosing brackets, inserting comma between chunks; append `]]`. Keep a bounded spooled temp file with max_size=1 MiB. After complete serialization, `tell()` is length; update digest with length and read file in 1 MiB chunks. Must close temp file reliably on exceptions; never create persistent corpus artifacts. No regular file on disk is modified by this procedure. Metadata may be immutable mapping or raw `info.metaData` dict and must use the same key-ordering as the old encoder.

Tests first: compile a node record of >20k nodes outside the tracemalloc window and compare SHA256 to current canonical `_digest_record` plus a deterministic expected reference hash; test unordered IDs, unicode combining marks, escaped spaces/pipes/backslashes, empty and missing values, integer negative values, and metadata key permutation. Assert peak intermediate `tracemalloc` allocation stays bounded relative to full serialized payload. Add a regression to existing tiny TF extraction asserting old/new snapshot identical. The real BHSA profiler workflow must pin the old loaded sha256, report before/after RSS and elapsed time under the same corpus/TF/feature counts, and store aggregate only. If RSS improves but time regresses substantially, document tradeoff before deciding merge. Full exact-head CI and independent adversarial review then merge; keep #20 open unless measured benefit is demonstrated and further bottleneck research considered.
