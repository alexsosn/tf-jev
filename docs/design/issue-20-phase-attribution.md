# Design: private opt-in schema extraction checkpoints

Keep public `extract_schema(api)` semantics unchanged and return the identical immutable CorpusSchema. Add keyword-only *private* `_phase_observer: Callable[[str], None]|None = None` for diagnostic tooling; its default path performs no new system calls and does not change identity. Forward to `_extract`. The private checkpoints run after (1) discovery, (2) feature load, (3) node/type index checks, (4) warp hashing, (5) all node-feature digests/counters, (6) edge features, (7) sources/identity, (8) domain/snapshot creation. The callback receives **only a fixed literal phase ID**, no loaded values. It may time each checkpoint using monotonic clock and `/proc` RSS independently.

Extend `scripts.profile_schema.profile_schema`: store `phases` in JSON as a list of `{name, seconds, rss_bytes, peak_process_rss_bytes}`, with sequential elapsed time since prior checkpoint. A callback after `domains` is emitted after creating snapshot, before returning to the profiling script. Return durations independent of the legacy total `extract_seconds`; use `< 2s` tolerance for sum in tiny corpus and a relative tolerance on real BHSA, so reporting is accurate without strict noisy time thresholds. Never emit feature names, corpus tokens, node IDs, absolute paths, or model text. Keep `--trace-python` optional only for tiny corpora.

RED tests commit before implementation: assert exact expected phase names and order on a tiny TF fixture, finite nonnegative time values, sorted-independent identity and schema output unchanged with/without observer, no data leakage, no externally visible callback for invalid input. Pinned real BHSA Actions asserts expected phase list and unchanged historical loaded-content SHA256; artifact stays counts-only JSON. Exact-head Python matrix, native CI, independent adversarial review gate. Do not close issue #20: results must still lead to a measured optimization.
