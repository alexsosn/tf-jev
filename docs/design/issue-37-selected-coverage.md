# Design: immutable feature coverage with fail-closed incomplete schemas

API `extract_schema(api, *, node_features: tuple[str,...]|None=None, edge_features: tuple[str,...]|None=None, _phase_observer=...)`: both None means **full** exactly as today. Specifying either argument explicitly opts into **selected** mode; the omitted other set becomes empty, not "all". Reject non-tuples, duplicate names, non-string, reserved or unknown names. Discovery uses TF.explore names; load only selected names, maintaining corpus's existing core/otext requirement. Ordering canonicalized to sorted tuples so permuted request order yields identical snapshot hashes.

Add frozen `FeatureCoverage(mode, node_features, edge_features, omitted_node_features, omitted_edge_features)` to `CorpusSchema`. In full mode the manifest is still available in Python but does **not** affect legacy loaded digest or serialized schema JSON. In selected mode, digest an additional `("feature-coverage-v1", sorted(selected_nodes), sorted(selected_edges), sorted(available_nodes), sorted(available_edges))` record before source metadata; produce `coverage` in JSON and ensure same manifest participates in Large handle identity. Unloaded feature access gives a **specific** SchemaError ("feature omitted from selected schema") rather than "unknown/excluded". Empty selected modes still validate warp data and source provenance. Full-mode schema output remains byte-compatible.

Node features and edges only include selected, inventories exactly count selected values. Unselected available names are an explicit discovered-only manifest (no value domains and no implied null/absent). For deterministic compiler, access to a selected feature is safe; accesses to unselected must fail. For SemanticParser, return `ParseStatus.UNSUPPORTED`, reason `incomplete_schema_coverage`, no backend calls until an explicit policy is implemented for incomplete coverage.

Profile CLI options `--node-features sp gn nu`, `--edge-features` (zero or more) and JSON coverage summary. Workflows should run full profile with historical exact digest and separate selected profile with **native query equivalence**, not a fixed expected subset digest; archive only summary hashes/counts/time/RSS. Future work may scope implicit otext loads only if independently shown safe.
